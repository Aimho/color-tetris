# 4단계: 서버 검증과 시즌 랭킹

## 구현 상태

코드 및 운영 설정 완료. Cloud Functions와 Firestore 규칙·인덱스를 배포했으며, 웹 App Check는 reCAPTCHA Enterprise와 7일 TTL로 등록하고 Firebase Authentication의 Google 제공업체를 활성화했다.
랭킹은 Firebase 익명 UID로 즉시 참여하며, Google 계정 연결은 5단계 마이페이지에서 선택적으로 제공한다.

- 서버 시드와 고정 버전 난수 생성기로 조각 순서를 결정한다.
- 잠금된 조각의 순서, 홀드, 위치, 회전, 도달 가능성과 충돌을 서버에서 재현한다.
- 색상 삭제, 화살표, 폭탄, 리액터, 배수 셀과 점수를 서버에서 다시 계산한다.
- 재현 결과가 원장과 일치하는 기록만 시즌·플랫폼별 최고 기록에 반영한다.
- 잘못된 제출은 실행권별 3회 후 거부하고, 대형 원장 요청을 제한한다.
- 랭킹에서는 프레임과 입력 장치에 따라 달라지는 드롭 점수를 사용하지 않는다.

## 검증 범위

서버 재현은 존재하지 않는 점수, 조각, 특수 셀과 불가능한 배치를 차단한다. 완전히 수정된 클라이언트나 자동 플레이 도구가 실제로 가능한 최적 배치를 대신 생성하는 것까지 판별하지는 않는다. 해당 위협은 향후 비정상 플레이 통계 탐지와 운영 제재 범위로 관리한다.

## 구현 범위

- 매월 KST 기준 새 시즌 생성, 이전 시즌 기록 보존
- 모바일과 데스크탑 랭킹 분리
  - 네이티브 앱 또는 터치 우선 입력: 모바일
  - 키보드 우선 웹: 데스크탑
  - 플랫폼은 게임 시작 시 고정
- 각 플랫폼 TOP 50과 사용자의 시즌 최고 기록 표시
- 정렬: 점수 내림차순, 레벨 내림차순, 달성 시각 오름차순
- 최고 기록은 자동 제출하며 더 높은 기록만 갱신
- 점수 원장에 시즌, 규칙 버전, 플랫폼, 플레이 시간, 직접·특수 삭제, 최대 체인, 리액터 및 배수 정보를 포함
- Cloud Function이 실행 토큰과 원장을 검증한 뒤 Firestore 기록
- App Check와 제출 속도 제한 적용
- 오프라인 종료 기록은 대기열에 저장 후 연결 시 제출

## 화면

- 현재 시즌 종료까지 남은 시간
- MOBILE/DESKTOP 탭
- 순위 밖에서도 보이는 MY BEST
- TOP 50 목록과 내 행 강조
- 로딩 중 목록 형태를 유지하는 스켈레톤

## 테스트

- 동점 정렬 규칙이 결정적이다.
- 직접 Firestore 쓰기는 거부된다.
- 다른 플랫폼·시즌·규칙 버전 토큰은 거부된다.
- 같은 종료 기록을 여러 번 보내도 한 번만 처리된다.
- 오프라인 대기열은 성공한 항목만 제거한다.
