# 요구사항 대비 구현 차이 기록

최종 갱신: 2026-07-26

확정된 요구사항과 실제 구현이 다르거나, 검증 환경 문제로 완료를 확인하지 못한 항목을 기록한다. 새로운 차이가 발견되면 이 문서에 누적하고 관련 작업 완료 보고에 포함한다.

## 구현 방식이 달라진 항목

### 시즌 배지 확정 시점

- 요구사항: 시즌 종료 시 TOP 1, TOP 10, TOP 50 및 개인 시즌 최고 기록 배지를 확정한다.
- 현재 구현: 시즌 종료와 마지막 랭킹 제출 유예 24시간이 지난 뒤, 사용자가 마이페이지를 열 때 종료된 미처리 시즌을 한 번에 하나씩 확정한다.
- 차이를 둔 이유: 모든 사용자를 정기적으로 스캔하는 예약 작업보다 Firebase 읽기 비용이 적고, 사용자별 처리 선점으로 중복 실행을 막을 수 있다.
- 영향: 마이페이지를 다시 열지 않은 사용자는 배지가 즉시 생성되지 않는다. 다음 마이페이지 진입 시 생성된다.

### 오프라인 랭킹 기록 재전송 시점

- 요구사항: 오프라인에서 종료된 기록을 보관하고 연결되면 다시 기록한다.
- 현재 구현: 마지막 미전송 랭킹 실행 한 건을 기기에 보관하고, 다음 랭킹 서버 상태 확인 시 재전송한다.
- 영향: 네트워크가 복구되어도 사용자가 랭킹 기능을 다시 이용하지 않으면 즉시 전송되지 않는다. 여러 미전송 실행을 대기열로 누적하지 않고 마지막 한 건만 유지한다.

## 검증이 남은 항목

### Firestore 보안 규칙 에뮬레이터

- 상태: 일반 테스트, Functions 테스트와 프로덕션 빌드는 통과했다.
- 미완료 사유: 현재 개발 환경은 Java 11만 설치되어 있고 Firebase CLI는 Java 21 이상을 요구한다.
- 필요한 조치: Java 21 이상 환경에서 `npm run test:rules`를 다시 실행한다.

### 모바일 실기기 UI

- 상태: 반응형 코드, 자동 테스트와 로컬 브라우저 HUD 구조를 확인했다.
- 미완료 사유: Android 및 iOS 실기기에서 최신 일시정지 팝업과 게임 방법 복귀 흐름을 아직 확인하지 않았다.
- 필요한 조치: 앱 패키징 단계에서 375px·390px 모바일, Android WebView와 iOS Safari/WKWebView를 검증한다.

## 의도적으로 유지한 위험

### 익명 UID의 랭킹 도전 횟수

- 확정 정책: 랭킹은 익명 UID로 바로 참여하고 소셜 계정 연결은 마이페이지의 선택사항으로 유지한다.
- 현재 위험: 익명 계정을 삭제하고 새 UID를 만들면 일일 3회 제한을 다시 받을 수 있다.
- 유지 이유: 이 위험을 완전히 막으려면 Google 등 지속형 계정을 강제하거나 별도의 설치 식별·속도 제한 체계가 필요하며, 현재 확정한 익명 참여 정책과 충돌한다.
