## 확장 회귀 테스트 시나리오

| 영역 | 조건·조작 | 기대 결과 |
|---|---|---|
| 랭킹 로딩 | 직전 게임 보드가 쌓인 상태에서 홈 복귀 후 랭킹 도전 | 첫 프레임부터 이전 셀이 보이지 않고 보드 전체 로딩 UI 표시 |
| 랭킹 로딩 | 느린 네트워크에서 랭킹 도전 | 보드 크기와 HUD 위치가 변하지 않고 로딩 문구 유지 |
| 랭킹 로딩 | 랭킹 버튼 빠르게 연속 탭 | 마지막 요청만 유효하며 게임이 중복 초기화되지 않음 |
| 랭킹 로딩 | 연결 중 탭을 백그라운드로 보냈다가 복귀 | 요청 결과가 유효하면 새 랭킹 보드, 무효면 홈 상태 유지 |
| 랭킹 오류 | 오프라인·App Check 실패·서버 타임아웃 | 로딩 UI 잔류 없이 홈에서 원인을 확인할 수 있는 오류 표시 |
| 튜토리얼 | 홈에서 열고 내부를 아래로 스크롤한 뒤 닫고 다시 열기 | 항상 안내 맨 위에서 시작 |
| 튜토리얼 | 모바일·데스크톱 각각 열기 | 현재 입력 환경에 맞는 조작법만 표시 |
| 튜토리얼 | 키보드 Escape 또는 상단 닫기 | 홈으로 복귀하고 열었던 버튼에 초점 복귀 |
| 일시정지 | 버튼 클릭·백그라운드 진입 | 저장 후 계속하기·홈으로 나가기 팝업 표시, 보드 입력 차단 |
| 일시정지 | 계속하기 | 타이머 급가속 없이 정상 속도로 재개 |
| 게임 오버 | 연습 모드 종료 | 서버 기록을 만들지 않고 점수·레벨·공유·홈 표시 |
| 게임 오버 | 익명 랭킹 모드 종료 | UID 최고 기록 자동 갱신, 실패 시 대기 기록 보관 |
| 플랫폼 | 터치 가능한 모바일 브라우저에서 랭킹 완료 | MOBILE 랭킹에 저장 |
| 플랫폼 | 마우스·키보드 데스크톱에서 랭킹 완료 | DESKTOP 랭킹에 저장 |
| 특수 셀 | 화살표·폭탄·배수 셀이 같은 폭발에 포함 | 고유 효과가 겹쳐도 보드 판정과 점수는 한 번만 반영 |
| 조작 | 모바일 연속 탭·길게 누르기·드래그 | 확대경·텍스트 선택·컨텍스트 메뉴 없이 게임 입력만 처리 |
| 조작 | 키보드 회전·이동·보관·즉시 낙하 | 페이지 스크롤 없이 한 번의 게임 입력만 처리 |
| 반응형 | 375×667, 390×844, 가로 회전 | 보드·HUD·팝업이 잘리지 않고 안전 영역 준수 |
| 접근성 | `prefers-reduced-motion: reduce` 활성화 | 랭킹 로딩 셀은 움직이지 않고 상태 문구는 유지 |
| 접근성 | 스크린 리더로 랭킹 로딩 | `role=status` 문구를 한 번 읽고 장식 셀은 읽지 않음 |

## 배포 후 확인이 필요한 항목

- 실제 Firebase App Check가 적용된 모바일 Safari와 Android Chrome에서 익명 랭킹 1회 완료
- 동일 익명 UID의 기록이 웹 TOP 50 및 내 기록에 함께 표시되는지 확인
- 네이티브 앱 출시 후 Android/iOS App Check ID가 모바일 버킷으로 분류되는지 확인
- 네트워크를 끊은 상태로 랭킹 종료 후 재접속했을 때 대기 기록이 자동 제출되는지 확인
- Firestore 규칙 테스트는 Java 21 환경에서 별도 실행
